# Create a restaurant or bar page

Build a restaurant or bar page with reservations, a structured menu, opening hours and directions. Check and publish the guest journey.

## Build and publish

Guests arrive with practical questions. A restaurant or bar page should answer them quickly, stay editable by the operating team and make optional experiences easy to understand.

1. Set the venue name, introduction and contact details in **Page**.
2. Put reservations or phone contact, hours and directions near the top of **Content**, using your existing reservation provider.
3. Create the structured **Menu**, review prices and dietary details, and add internal navigation to its published destination.
4. Save and check the main page and menu. Test the final QR destination on a phone before displaying or printing it.

<a id="problem"></a>

## The guest should not hunt across a PDF, social profile and map listing

Menus, reservations, opening information and directions often live in different systems. OrbitPage brings the routes together while keeping the native menu as a dedicated, readable destination.

<a id="structure"></a>

## Put booking and today's useful information first

Start with a reservation or call action, then menu, opening information, location and current events. Keep social profiles compact so they support the page rather than becoming the page.

- Reservation or phone action
- Native menu and availability
- Hours, location and directions
- Events, seasonal updates and social

<a id="menu"></a>

## Update an item without replacing a document

Sections, subsections, descriptions, prices, variants, allergens and availability are managed from the workspace. A table QR can point directly to the menu while the main page continues to serve visitors from social or search.

<a id="ai"></a>

## Refresh the story around the menu without rebuilding the page

Use AI to prepare changes to introductions, event blocks, links and page styling when a season or service changes. The menu remains deliberate structured content, while AI helps the surrounding page stay concise and current.

Every proposed edit remains visible for review before it is applied.

<a id="shop"></a>

## Sell an experience—not every table

A fixed-price tasting, workshop or bookable private experience can be offered as a service with payment, booking details and intake questions. Standard reservations should continue through the booking system the team already operates.

OrbitPage Shop is not a table-management or restaurant POS system.

<a id="pilot"></a>

## Begin with the information staff already maintain

A useful pilot does not require a new content strategy. Reuse the approved menu, reservation destination, phone, location and current visual identity, then add campaigns only after the daily information is reliable.
