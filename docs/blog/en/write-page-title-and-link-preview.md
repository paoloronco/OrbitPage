# How to write a page title and link preview people can trust

Write a browser title, description and social preview that identify the same page visitors will see after opening the link.

OrbitPage · 2026-09-17 · English

[Read on OrbitPage](<https://orbitpage.com/en-US/blog/write-page-title-and-link-preview>) · [Browse the archive](<https://github.com/paoloronco/OrbitPage/tree/main/docs/blog>)

The words beside a shared URL shape a visitor's expectation before the page loads. A title or preview cannot repair a weak destination, but it can accurately identify the person, offer or event behind the link. Start with the visible page, then write metadata that matches it.

<a id="title"></a>

## Put the subject and purpose in the browser title.

A useful title might combine a business name and a defined service, or an artist and the current release. A generic 'Home' gives little context to someone seeing the result outside a familiar social profile.

Keep the visible heading aligned with that title. If the page now promotes an event while the browser title still advertises last year's offer, update both.

<a id="description"></a>

## Describe the actual next step without repeating keywords.

Use the description to add one useful detail: service area, current program, product type or booking route. Avoid claims that are not on the page. Search engines may choose their own snippet from the page, so visible copy still matters.

Write for a person deciding whether to open the link. A precise, ordinary sentence is more useful than a list of variations of the same search phrase.

<a id="preview"></a>

## Check the image and text on the channels you use.

Link preview services can cache titles and images, and different apps may show different crops or text. Share the public URL in a test conversation after publishing and confirm that the visible preview still represents the current page.

Use recognizable imagery and readable text; do not place critical event details only in a tiny preview image. The page itself must carry the complete answer.

<a id="change"></a>

## Update metadata when the page's job changes.

A durable page address can serve new campaigns, but the title and description should follow the current content. Record the change date and inspect the live page after publication, especially when moving to a custom domain.

If search results display older wording for a while, check the public HTML and allow time for recrawling. A correct metadata field is a signal, not a command that every search or social service must display verbatim.
