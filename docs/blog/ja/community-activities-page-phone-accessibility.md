# スマートフォンで使いやすいコミュニティ活動ページを作る

定期開催の活動ページをシンプルにし、リンクを分かりやすく整え、役立つ画像説明を追加し、スマートフォンでアクセシビリティを確認するための実践ガイドです。

OrbitPage Editorial · 2026-11-26 · 日本語

[Read on OrbitPage](<https://orbitpage.com/ja-JP/blog/community-activities-page-phone-accessibility>) · [Browse the archive](<https://github.com/paoloronco/OrbitPage/tree/main/docs/blog>)

![毎月のお知らせを、次の行動が分かりやすい内容にする](<https://orbitpage.com/api/blog/illustrations/community-activities-page-phone-accessibility?v=2&locale=ja>)

コミュニティのページに複数の活動、日程、申し込みリンクがまとめて掲載されていると、スマートフォンで見る人は、どれが最新の情報なのか、どの操作をタップすればよいのか分かりにくくなることがあります。次に何をすればよいかがすぐ分かるよう、順序やラベル、操作部品を工夫すると、簡潔なページをより使いやすくできます。

<a id="section-1"></a>

## 次に役立つ操作を最初に配置する

まず、訪問者の多くが何をする必要があるかを考えましょう。次の集まりを見つける、参加枠を予約する、または道順を確認する、といったことです。すべての活動を同じ比重で扱うのではなく、そのニーズを中心にページを構成します。短い導入文でグループを紹介し、このページで何ができるかを伝えましょう。

各活動には分かりやすい見出しを付け、日付と場所をその近くに記載します。ラベルとリンク先から操作内容が分かるなら、リンクだけで十分です。日時と申し込みに関する情報をひとまとまりにする必要がある場合は、イベント形式のブロックを使いましょう。OrbitPageでは、情報に合ったコンテンツブロックを選べるため、細部ごとにブロックを追加せず、ページを簡潔に保てます。

<a id="section-2"></a>

## 曖昧なラベルを、操作内容が分かる文言に置き換える

「ここをクリック」や「詳細」のようなラベルでは、特にリンクが文脈から切り離されて読み上げられる場合、リンク先が分かりません。リンク先や操作内容を直接示しましょう。目で追いやすい短さを保ちながら、ほかのリンクと区別できるだけの具体性を持たせます。

定期開催の活動なら、「土曜のガーデニング活動の詳細を見る」や「修理カフェの参加枠を予約する」などの表現を試してみましょう。申し込みフォームが別のサービスにある場合は、周囲の文言でそのことを明示します。「登録は外部の申し込みフォームから行えます。」OrbitPageではそのリンク先へのリンクを表示できますが、予約そのものは外部サービスが処理します。

変更前と変更後：「参加する」を「5月12日のコミュニティ散策に申し込む」に変更します。「場所を確認する」を「図書館の会議室への道順を見る」に変更します。こうしたラベルなら、何をするのか、操作するとどこに移動するのかの両方が訪問者に伝わります。

![日付を最初に示す → 集合場所を追加する → 操作内容を明示する → 写真を説明する](<https://orbitpage.com/api/blog/illustrations/community-activities-page-phone-accessibility?variant=steps&v=2&locale=ja>)

月例のお知らせを、次の行動が分かる内容に変えましょう。説明用の例です。

<a id="section-3"></a>

## 仮想の例：月例のお知らせを分かりやすくする

架空のグループ「Riverside Neighbours」に、月例のごみ拾い、工具の共有会、連絡先リンクを載せた簡潔なページがあると想像してください。現在のページは一般的な歓迎文から始まり、「詳細」というリンクが複数並び、ボランティアの写真には何が写っているか説明がありません。

次のごみ拾いが最初に表示されるように並べ替えます。「次回のごみ拾い：5月18日（土）」という見出しの下に、「10:00にミル・パーク東門に集合」と記載します。予約フォームが開くならリンクに「5月18日のごみ拾いに申し込む」、情報ページが開くなら「ごみ拾いの詳細を見る」というラベルを付けます。その下に工具の共有会を置き、最後に直接連絡できる方法を示します。

写真が役立つ情報を加える場合は、「公園の小道のそばでごみを拾うボランティア」のような代替テキストを付けます。画像が装飾のみで情報を加えない場合、近くにある活動の見出しをaltテキストで繰り返す必要はありません。代替テキストでは、画像の関連する目的を伝え、視覚的な細部をすべて説明する必要はありません。

<a id="section-4"></a>

## 判断に必要な情報を隠さず、ページを簡潔に保つ

余分な情報を取り除くとページを見やすくできますが、圧縮しすぎると訪問者が迷うことがあります。スペースを節約するためだけに、日付、集合場所、申し込み条件を省かないでください。それらの情報は関連する活動のそばに置き、導入文の繰り返しや同じ場所に移動するリンクを削除しましょう。

定期開催の活動をすべて一度に表示するか、次回の活動を優先するかが、検討すべきトレードオフです。予定全体を表示すれば、訪問者は先の計画を立てやすくなります。一方、次の日程を最初に置けば、すぐに行動したい人に分かりやすくなります。「その他の定期活動」という短いセクションを設ければ、次のイベントを目立たなくすることなく、全体の予定も残せます。

<a id="section-5"></a>

## スマートフォンでページを実際に確認する

プレビューは便利ですが、公開済みのページを実際に使うことの代わりにはなりません。スマートフォンまたは幅の狭いブラウザーウィンドウで開き、可能であれば文字サイズを大きくして、マウスに頼らず操作してみましょう。見出しが順番に読んで意味が通ること、キーボードでリンクに移動して操作できること、フォーカスが見える状態に保たれることを確認します。拡大表示して、横スクロールを強いられずに操作部品が収まるかも確かめましょう。

ページを共有する前に、次の最終チェックリストを使ってください。レイアウトやエディターの設定でアクセシビリティを確認できたと決めつけず、主な閲覧・操作のタスクを確認できます。

-   訪問者は、次の活動、日付、集合場所をひと目で確認できますか？
-   外部の申し込みフォームを含め、リンクのラベルから操作内容やリンク先が分かりますか？
-   情報を伝える画像には、それぞれ簡潔で関連性のある代替テキストがありますか？
-   すべての操作部品にキーボードで移動でき、どれにフォーカスがあるか分かりますか？
-   画面幅が狭く文字が大きい状態でも、横スクロールせずにページを使えますか？
