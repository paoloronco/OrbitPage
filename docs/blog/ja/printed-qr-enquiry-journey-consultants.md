# 独立系コンサルタントのための、印刷QRコードから問い合わせまでの導線設計

印刷したQRコードから、見込み顧客を目的に合ったモバイル対応のプロジェクト問い合わせページへ案内するための実践的な手順をご紹介します。

[Read on OrbitPage](<https://orbitpage.com/ja-JP/blog/printed-qr-enquiry-journey-consultants>) · [Browse the archive](<https://github.com/paoloronco/OrbitPage/tree/main/docs/blog>)

![会議の配布資料から、役立つ問い合わせへ](<https://orbitpage.com/api/blog/illustrations/printed-qr-enquiry-journey-consultants?v=2&locale=ja>)

QRコードが問題なく読み取れても、見込み顧客が次に何をすればよいのかわからないことがあります。独立系コンサルタントにとって、印刷物、ページ、問い合わせまでの導線は、ひと続きの短い体験として機能する必要があります。

<a id="section-1"></a>

## スキャンする瞬間から考える

見込み顧客がコードを目にする場所を決めましょう。会議の配布資料、提案書、プレゼンテーションのスライド、印刷した紹介資料などが考えられます。その場面によって、最初に伝えるべき内容が変わります。サービスの説明を聞いたばかりの人には、自分に合うかどうかをすばやく判断する方法が必要です。一方、持ち帰り用の資料を読む人には、より詳しい情報が必要かもしれません。

説明のない画像としてコードを置くのではなく、具体的な呼びかけのそばに配置しましょう。たとえば、「サービスの再設計をお考えですか？スキャンして、目標とスケジュールをお聞かせください。」という文言なら、何ができるのかが伝わり、スキャンする意味があるかを読み手が判断しやすくなります。

コードの周囲には十分な余白を取り、折り目や光沢による反射が出る場所、手やラベルで隠れやすい場所は避けましょう。レイアウトが許す場合は、読みやすい短い代替URLも記載します。そうすれば、次のステップがカメラだけに依存しません。

<a id="section-2"></a>

## 最新の状態を保てるリンク先を選ぶ

コードのリンク先には、一時的なキャンペーンや予約ページではなく、自分で管理でき、今後も役立つ状態に保てるページを指定しましょう。印刷したコードは、配布後に差し替えるのが困難です。公開アドレス自体が引き続き利用できるなら、安定したページを使うことで、印刷し直さずに文言や問い合わせ方法を変更できます。

OrbitPageのページは、公開ワークスペースのアドレスまたは有効なカスタムドメインで共有できます。カスタムドメインを使う場合は、その所有権、ルーティング、HTTPSの準備が整ってからアドレスを印刷してください。公開ページを開く前に、ページの編集内容を保存しましょう。未保存のプレビューは、訪問者に表示される内容を変えません。

ページの主なアクションは明確にしつつ、すべての訪問者に予約の手続きを強制しないようにしましょう。予約サービスは外部のリンク先ですが、OrbitPageのページでサービスを説明し、そのサービスや別の問い合わせ方法へ訪問者を案内できます。

会議の配布資料から、有意義な問い合わせへ。説明用の例です。

<a id="section-3"></a>

## スマートフォンを手にした訪問者に合わせて作る

読み手は立ったまま、気が散る状況で、小さな画面を見ていると想定しましょう。ページの上部にはサービス内容と対象となる顧客を置き、その後に、引き受けるプロジェクトの種類を簡潔に説明し、次のステップを明示します。訪問者が長いリンク一覧を探し回らなくて済むよう、補足情報は主要なアクションより下に配置しましょう。

問い合わせ時に必要な情報を尋ねると、ページを本格的な提案依頼フォームにせずに、内容を充実させることができます。たとえば、プロジェクトの目標、現在の段階、希望する時期、連絡方法を記入してもらいましょう。外部のフォームや予約ツールに案内する場合は、移動が想定外にならないよう、そのことを明確に伝えます。

十分な情報を集めることと、連絡のしやすさとの間には、現実的なトレードオフがあります。質問を増やせば相性を判断しやすくなりますが、すぐに話を始めたい人を遠ざける可能性もあります。次の返信内容を左右する情報だけを尋ねましょう。

<a id="section-4"></a>

## 仮定に基づく実例：会議の配布資料

架空のコンサルタント、マヤは、小規模チームにサービス再設計の助言をしています。彼女の配布資料は、会議で短い会話を交わした直後の人に届きます。そのため、QRコードのリンク先では、一般的なプロフィールを表示するのではなく、相性を確かめ、有意義な最初の問い合わせを送れるようにする必要があります。

コードの横には、配布資料にこう記されています。「サービスの再設計をお考えですか？スキャンして、相性を確認し、プロジェクトの概要をお送りください。」ページの上部で、マヤはこう説明します。「小規模チームが、わかりにくいサービスを使いやすくできるよう支援しています。うまくいっていないことと、実現したいことをお聞かせください。」引き受けるプロジェクトの種類を短い段落で説明し、その後に「プロジェクトの背景を共有する」と表示された問い合わせアクションを置きます。

ページでは、プロジェクトの目標、現在の段階、希望する時期を尋ね、連絡先の入力は任意にします。外部フォームを使う場合、マヤはフォームのタイトルと最初の質問が配布資料での約束と一致しているかを確認します。QRコードのリンク先は安定した公開ページにしておくため、印刷したコードを変えずに、後から問い合わせ方法を更新できます。

<a id="section-5"></a>

## 印刷物からページまでの導線全体を承認する

印刷用データを入稿する前に、プレビューやコードを生成できたという事実だけに頼らず、新しい訪問者になったつもりで導線をテストしましょう。完成版のデータを実際に使うサイズで用意し、使用する場所でスマートフォンからスキャンして、次のアクションまで一連の流れを確認します。これは手作業で行う確認です。QRコード自体は、ページや外部フォームが最新であることを確認してくれません。

最終確認を承認の関門にしましょう。コードの横に印刷した案内と、ページおよび問い合わせまでの導線で実際に提供される内容を照らし合わせ、校正刷りを配布してよいか判断します。

-   コードが、編集画面やプレビューではなく、意図した公開アドレスに解決されることを確認します。
-   代替URLが読みやすく、印刷したリンク先と一致することを確認します。
-   問い合わせ先が利用可能で、役立つプロジェクト情報だけを尋ねていることを確認します。
-   ページと印刷物の案内が同じ約束を伝えている場合にのみ、校正を承認します。
